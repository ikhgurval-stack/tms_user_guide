# Хэрэглэгчийн удирдлага (User Management)

## Зорилго

Driver App болон Store App-д ажиллах хэрэглэгчийн бодит жишээг таньж, SYS хэрэглэгчийн бүртгэлээс ямар мэдээллийг нэмж баталгаажуулах шаардлагатайг ойлгоно.

TC-B2C-E2E-001-д жолоочийн болон дэлгүүрийн хэрэглэгч ашигласан. Харин SYS дээр хэрэглэгч үүсгэсэн, эрх оноосон дэлгэц repository-д байхгүй.

## Урьдчилсан нөхцөл

- [Байгууллагын удирдлага](business-organization.md)-ын тайлбартай танилцана. Байгууллагын харьяалал заавал шаардах эсэхийг тодруулна.
- Ямар ажил гүйцэтгэх хэрэглэгч хэрэгтэйг тогтооно: Driver App-ийн хүргэлт эсвэл Store App-ийн хүлээн авалт, үнэлгээ.
- Хэрэглэгчийн бүртгэл үүсгэх, өөрчлөх эрхтэй эсэхээ систем хариуцсан ажилтнаас тодруулна. Эрхийн яг нэр баталгаажаагүй.

## Цэсний зам

**SYS → Platform System Management → User Management**

Repository-д бүртгэгдсэн модулийн шатлал. Бүртгэл үүсгэх болон role оноох дэд үйлдлийн байрлал баталгаажаагүй.

## Шинээр үүсгэх / тохируулах

Шинэ хэрэглэгч бэлтгэхээс өмнө дараах бодит жишээг ялгаж ойлгоно:

1. **Driver user:** тестэд **[B2C-DRV05] Мөнхөө** жолоочийн даалгаврыг гүйцэтгэсэн. **B2C-DRV05** нь жолоочийн код; SYS хэрэглэгчийн код эсвэл нэвтрэх нэр мөн эсэхийг баталгаажуулаагүй.
2. **Store user:** **qqB2C-DP-032** хэрэглэгчээр Store App-д нэвтэрч, **B2C Home 032** дэлгүүрийн хүлээн авалтыг шалгасан.
3. Тухайн хэрэглэгчид ямар organization, role, ажилтны бүртгэл холбохыг систем хариуцсан ажилтантай тодруулна. Эдгээр холбоог хадгалах үйлдэл эх сурвалжид байхгүй.
4. Шинэ хэрэглэгч үүсгэх маягтын талбарууд болон шаардагдах утгуудыг баталгаажуулсны дараа дэлгэрэнгүй зааврыг нөхнө.

Store хэрэглэгчийг хүргэлтийн цэгт автоматаар эсвэл тусгай функцээр үүсгэдэг гэсэн өмнөх тэмдэглэл бий. Аль аргыг ашигласныг эх сурвалж тодорхойлоогүй тул SYS-ээс заавал гараар үүсгэнэ гэж заагаагүй. [Үндсэн өгөгдлийн тайлбар](../getting-started/overview.md).

## Талбарын тайлбар

Доорх нэршил нь тайлбарлах мэдээллийн төрөл бөгөөд **User Management маягтын баталгаажсан UI талбарын нэр биш**. SYS талбарын screenshot байхгүй тул заавал бөглөх эсэхийг тогтоогоогүй.

| Талбар | Тайлбар | Заавал эсэх | Жишээ |
| ------ | ------- | ----------- | ----- |
| Хэрэглэгчийн код (user code) — UI нэр баталгаажаагүй | Store нэвтрэлтэд ашигласан хэрэглэгчийн нэр бий; SYS кодтой ижил эсэх тодорхойгүй | Баталгаажаагүй | qqB2C-DP-032 |
| Нэр — UI нэр баталгаажаагүй | Жолоочийн нэр хүргэлтийн даалгаварт харагдсан; SYS хэрэглэгчийн нэрийн талбарын нотолгоо биш | Баталгаажаагүй | Мөнхөө |
| Утас (phone) — SYS UI нэр баталгаажаагүй | Жолоочийн холбоо барих утас; нэвтрэх нэр гэж үзэхгүй | Баталгаажаагүй | 88000005 |
| Төлөв (status) — UI нэр баталгаажаагүй | Хэрэглэгчийн төлөв, боломжтой утгууд өгөөгүй | Баталгаажаагүй | Байхгүй |
| Байгууллагын харьяалал (organization) — UI нэр баталгаажаагүй | Аль байгууллагад харьяалагдсан, сонгох шаардлагатай эсэх тодорхойгүй | Баталгаажаагүй | Байхгүй |
| Эрх оноолт (role assignment) — UI нэр баталгаажаагүй | Driver / Store role ашигласныг хэрэглэгчийн өгсөн тестийн тайлбарт дурдсан; оноосон арга, эрхийн код байхгүй | Баталгаажаагүй | Driver / Store — тайлбарт дурдсан нэршил |
| Ажилтантай холбох — UI нэр баталгаажаагүй | Жолоочийн бүртгэл ашигласан нь SYS user-ийг Employee бүртгэлтэй холбох аргыг батлахгүй | Баталгаажаагүй | B2C-DRV05 — жолоочийн код |

## Хадгалах

SYS хэрэглэгч хадгалах товч, амжилтын мэдэгдэл, давхардлыг шалгах дүрэм эх сурвалжид байхгүй. TODO: хэрэглэгч үүсгэх маягт, хадгалсан бүртгэл болон бодит үр дүнгийн зураг авах.

Нууц үгийн анхны утга, үүсгэх дүрэм, нэвтрэх арга, утасны дугаараар баталгаажуулах шаардлага өгөөгүй.

## Бүртгэлийг шалгах

Одоо байгаа тестийн үр дүнг дараах холбоосоор тулгана:

1. Driver хэрэглэгчид **B2CVS260922000001** нийтэлсэн даалгавар **Current** хэсэгт харагдсан эсэх: [даалгавар нийтлэх](../dispatch/publish.md).
2. Store хэрэглэгч **qqB2C-DP-032** нь **B2C Home 032**-ын **Receipt List → Received** хэсгийг шалгасан эсэх: [Store App](../execution/store-app.md).
3. Store App-аас илгээсэн үнэлгээ Web дээр үнэлэгчийн мэдээлэлтэй харагдсан эсэх: [үнэлгээ шалгах](../execution/store-app.md#3-web-tms).

Эдгээр нь бэлэн хэрэглэгчээр гүйцэтгэсэн ажиллагааны нотолгоо. SYS бүртгэл зөв үүссэн, organization болон role зөв оноогдсоныг дангаар нь батлахгүй.

## Засварлах

Өөрчилж болох талбар, хадгалах арга, өмнөх даалгаварт үзүүлэх нөлөөг баталгаажуулаагүй. TODO: хэрэглэгчийн дэлгэрэнгүй бүртгэл болон засварын өмнөх, дараах үр дүнг баримтжуулах.

## Идэвхгүй болгох / боломжтой төлөвийн өөрчлөлт

Хэрэглэгчийг идэвхгүй болгох үйлдэл, төлөвийн нэр, нэвтрэлтэд үзүүлэх нөлөө баталгаажаагүй. Хүргэлтийн **Completed**, хүлээн авалтын **Received** нь хэрэглэгчийн бүртгэлийн төлөв биш.

## Анхаарах зүйл

- Тестийн код, утас, хэрэглэгчийн нэр нь жишээ өгөгдөл; шинэ хэрэглэгч бүртгэхэд хуулж ашиглах утга биш.
- Driver App-д ажилласан жолоочийн кодыг SYS user code гэж дүгнэхгүй.
- Role оноох дэлгэрэнгүй хүрээг [Role Management](role-management.md)-ээс харна.
- Дутуу screenshot: хэрэглэгчийн жагсаалт, үүсгэх маягт, organization болон ажилтны холбоос, role оноолт, хадгалсан бүртгэл, засвар болон төлөвийн өөрчлөлт.

## Түгээмэл алдаа

Хэрэглэгч үүсгэх эсвэл нэвтрэх үеийн баталгаажсан алдааны мэдэгдэл байхгүй. Нэвтрэх боломжгүй тохиолдлыг шууд role эсвэл organization-тай холбон тайлбарлахгүй; бодит мэдэгдэл болон тохиргоог систем хариуцсан ажилтнаар шалгуулна.
