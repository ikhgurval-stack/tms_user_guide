# Харилцагчийн мэдээлэл (Customer Information)

[TMS-ийн тойм](index.md)

## Энэ хэсэг юу хийдэг вэ?

Энд харилцагч болон түүнд харьяалах ачилтын, хүргэлтийн цэгүүдийг бүртгэнэ. Ачилтын цэг нь бараа хаанаас ачигдахыг, хүргэлтийн цэг нь хаана хүргэгдэхийг тодорхойлно. Эдгээр нь тээврийн захиалга бэлтгэх үндсэн мэдээлэл юм.

Мөн хүргэлтийн цэгүүдийг тогтмол маршрутад оруулах, бүсээр бүлэглэх боломжтой. Маршрут болон бүс үүсгэсэн нь захиалга, хүргэлтийн даалгавар автоматаар үүссэн гэсэн үг биш.

**Цэсний зам:** TMS → Customer Information → тохирох дэд цэс.

## Гол ойлголтууд

| Ойлголт | Зориулалт | Заавар |
|---|---|---|
| Client — Харилцагч | Ачилтын болон хүргэлтийн цэгүүдийн үндсэн харьяалал. Өмнөх B2C зааварт захиалагч гэж мөн нэрлэсэн. | [Client Management](customer-information/client-management.md) |
| Loading Point — Ачилтын цэг | Бараа ачигдах газар. | [Client Loading Point](customer-information/client-loading-point.md) |
| Delivery Point — Хүргэлтийн цэг | Барааг хүргэх бодит газар. | [Client Delivery Point](customer-information/client-delivery-point.md) |
| Fixed Route — Тогтмол маршрут | Харилцагчийн маршрутын төлөвлөгөө дотор хүргэлтийн цэгүүдийг маршрутаар бүлэглэнэ. | [Fixed Route](customer-information/fixed-route.md) |
| Region Division — Бүсийн хуваарилалт | Харилцагчийн хүргэлтийн цэгүүдийг бүсэд харьяалуулна. | [Region Division](customer-information/region-division.md) |

Холбоог энгийнээр харуулбал:

- **Харилцагч → Ачилтын цэг / Хүргэлтийн цэг** — харилцагчийн дэлгэрэнгүйд хоёр төрлийн цэг тусдаа хүснэгттэй.
- **Маршрутын төлөвлөгөө → Маршрут → Хүргэлтийн цэг** — тогтмол маршрутын дэлгэрэнгүйд бүлэглэгдэнэ.
- **Бүс → Хүргэлтийн цэг** — бүсийн дэлгэрэнгүйд харьяалах цэгүүд харагдана.
- **Хүргэлтийн цэг → Store хэрэглэгч → Store Mini App** — дэлгүүрийн талаас хүлээн авалтын мэдээлэл шалгах, үнэлгээ илгээхтэй холбоотой.

## Анх удаа тохируулж байгаа бол

### Санал болгож буй бэлтгэх дараалал

1. [Харилцагч үүсгэх](customer-information/client-management.md).
2. [Ачилтын цэг бүртгэх](customer-information/client-loading-point.md).
3. [Хүргэлтийн цэг бүртгэх](customer-information/client-delivery-point.md).
4. Хэрэгтэй бол [Store хэрэглэгч үүсгэх тохиргоо](customer-information/client-delivery-point.md#store-user)-г хийх.
5. Хэрэгтэй бол [тогтмол маршрутын төлөвлөгөө](customer-information/fixed-route.md) бэлтгэх.
6. Хэрэгтэй бол [бүс үүсгэж хүргэлтийн цэг холбох](customer-information/region-division.md).
7. Дараа нь [тээврийн захиалгын мэдээллээ](../transportation-order/overview.md) бэлтгэх.

Энэ нь системийн заавал мөрдөх шалгалтын дараалал биш. Тогтмол маршрут, бүс, Store хэрэглэгчийг бүх захиалгад заавал шаардана гэсэн дүрэм одоогийн тестээр баталгаажаагүй.

## Бодит жишээ

[Үндсэн өгөгдөл бэлтгэх](../getting-started/overview.md) болон [TC-B2C-E2E-001](../testing/tc-b2c-e2e-001.md)-д:

| Бүртгэл | Тестийн утга |
|---|---|
| Харилцагч | B2C-DEMO / BDC |
| Ачилтын цэг | DEMO-DC01 — Demo Distribution Center |
| Хүргэлтийн цэгүүд | B2C-DP-031 — B2C Home 031; B2C-DP-032 — B2C Home 032 |
| Store хэрэглэгч | qqB2C-DP-032 |

Эдгээр нь тестийн жишээ болохоос шинэ бүртгэлд хуулж ашиглах утга биш. Шинэ заавар нь 22 дэлгэцийн зураг болон өмнөх тестийн баримтад тулгуурласан. Маягтын хадгалалт, бизнесийн урсгалыг энэ ажлаар систем дээр дахин туршаагүй.
